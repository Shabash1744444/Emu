# CP189 — World 0.67.0, G3.0G и сменные профили ABI

Ядро первично. Все 43 Python-файла тестовой копии синхронизированы байт в байт с оригинальным G30G ZIP. Четыре закона и языковые механизмы не изменены. main не затронут.

## Установка

Обновить установленный C4 Nursery World новым APK. Для G30G использовать уже скачанные оригинальные файлы:

- `C4_G30G_ANDROID_LIVE_RUNTIME_2026-10-12.zip`: SHA-256 `f4fd3f7810a35d4211efa694a46236af177b843b7800c40d09d5fc455613aeb7`.
- `C4_G30G_ANDROID_LIVE_RESEARCH_ORGANISM_2026-10-12.c4m`: SHA-256 `8c6d102a178493ef3782a4aa2620e7dd12cbae5854a217cad92eae329b332dac`.

Перед сменой runtime остановить C4. Новая схема не переименовывается в G30D. Старое рабочее состояние остаётся на месте; автоматической миграции одной жизни между разными исходниками нет. Ошибка CHECKPOINT_ORGANISM_OR_RUNTIME_MISMATCH сохраняет обе стороны для отдельной проверяемой миграции. Не удалять данные приложения ради запуска.

## Контракт до и после

| Граница | До | Теперь |
|---|---|---|
| Исходники runtime | Один фиксированный профиль G30D | Встроенные точные профили G30D/G30G; отдельный импорт профиля разработчика |
| Схема | Только C4M_G29_G30C_G30D_LIVE_LAB_V1 | Схема выбранного точного профиля; проверка cp.SCHEMA |
| G29Graph | Четыре сохраняемых компонента | Четыре либо пять с binding_state; неизвестный состав отвергается |
| G30G binding | Не сохранялся старым хостом | Полное binding.state(), включая вопросы, гипотезы, claims, roots и learned extractor |
| Готовность | Импорт похож на готовность | Импорт требует handshake организма и callable методов |
| Диалог | Реальные события / диагностика | Тот же маршрут; профиль не создаёт ответы |
| История | Native append-only + checkpoints | Сохранена; нет перезаписи всего журнала на каждом такте |

## Следующие релизы без пересборки APK

Если разработчик подтвердил прежний контракт состояния и методов, он может подготовить JSON:

```
python3 tools/create_runtime_profile.py --runtime ORIGINAL.zip --abi DECLARED_ABI --output developer-profile.json
```

Команда извлекает статическую схему и SHA-256 исходников, не меняя ZIP. Это описание идентичности, а не доказательство совместимости или корректности когнитивной архитектуры. Разработчик обязан проверить сериализацию, перечень состояния и перезапуск реального организма. В приложении: Система → Импорт профиля разработчика, затем обычный Runtime ZIP / .c4m. USER_IMPORTED явно отличается от BUNDLED_REVIEWED в handshake. Импортировать только профиль и код от доверенного разработчика: Python runtime является исполняемым кодом.

Новые обязательные методы/компоненты состояния требуют нового адаптера. Результат UNSUPPORTED с точной причиной; произвольная будущая C4 автоматически не поддерживается. Проверка сигнатур не может доказать семантическую совместимость. Конфликт двух профилей на одни исходники запрещён. Неизвестные или изменённые исходники не заменяют установленный runtime.

## Проверки

- Python: прежние 10 тестов на малом объявленном CI организме PASS.
- G30G: четыре дополнительных теста PASS: native ASK → первая гипотеза → сохранение → второй вариант ответа → предварительный self-report → холодный отдельный процесс с точным восстановлением provenance/journal; отрицательные контрпримеры; сменный профиль; отсутствующий метод.
- G30D: запуск и точное восстановление малого организма PASS с прежними исходниками.
- JavaScript syntax, UI bindings, layout guard PASS.
- Полный оригинальный G30G организм: все 10 тестов PASS за 56.277 s, включая restart, crash replay, конкурентный ввод, повреждение checkpoint и неизменность импортированного файла.
- APK BUILD и browser smoke: проверяются GitHub Actions.
- PHYSICAL ANDROID VERIFIED: нет. Эти проверки не заменяют телефон.

Собственный аватар пользователя, joystick/look, gamepad, настройка управления и комната сохранены. WORLD_EVENT для данного исследовательского runtime остаётся UNSUPPORTED; физика Android не выдаётся за обучение C4. G30G self-report не удостоверяет личность. Свободный разговорный русский и новая голосовая способность не заявляются.
